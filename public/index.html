Fizzlayer Gateway

The secure connection layer for AI agents.

Fizzlayer Gateway is one MCP endpoint in front of the servers your agents can call. You allow a tool, deny it, or hold it for approval. If the tool's description changes, the call stops until you pin the new text.

How a call moves

The risky call waits. The agent tries again.

  1. 1

    The client presents a Fizzlayer JWT

    ES256, issuer fizzlayer, audience set to that gateway's URL. The public key is at /api/gateway/jwks.

  2. 2

    fizz-guard reads the rule

    Each tool is allow, deny, or approve. No matching rule denies the call. A tool you have not pinned is hidden from the list by default, and a call to it is denied.

  3. 3

    Approval is one retry

    The gateway rejects the call, stores the argument hash, and returns. You approve that row. The same call is allowed once, then a second retry is rejected.

In the data plane

Rules, pins, and tokens.

These are the pieces in gateway/. Longer notes are in the docs.

Per-tool policy

Allow, deny, or approve. A rule can name one server or every server, and one tool or *. Notifications are a log line, a webhook, or a phone call.

Tool pinning

The pin is a hash of the tool name, description, and input schema. A changed description drops the tool from tools/list and blocks tools/call until you approve the new hash.

Single-use approval

The rejection names an id and tells the agent to retry the same call. The default window is 10 minutes. Approving it does not approve the next different argument list.

Client JWTs

Mint a token for "Cursor on this laptop", revoke it later. fizz-guard reads revoked_at. The default life is 1 hour. You can ask for up to 30 days.

Encrypted upstream keys

An MCP API key is stored as AES-256-GCM ciphertext. List responses do not include it. The signed-in config preview leaves credentials out.

Hot reload from a file

Standalone mode writes agentgateway YAML and replaces the file in one rename, which the proxy watches. Linked mode runs fizz-agent, which polls the control plane and writes that same file. Do not run both writers on one file.

Quickstart

Docker from the repo, or a place on the hosted list.

Self-host

Docker Engine with Compose. The script builds the local image, checks the database policies, and runs an MCP client through the gateway. It removes the containers when it finishes. Passwords stay in gateway/compose/.env and are not printed.

git clone --depth 1 https://github.com/fizzlayer/fizzlayer.git
cd fizzlayer
gateway/compose/test.sh

To leave the sample gateway listening on 127.0.0.1:3000, use the compose command in the docs. Linked mode is gateway/compose/test-linked.sh, or fizz-agent pull against your own control plane. Docker Hub does not have a fizzlayer/fizzlayer-gateway tag yet, so Compose builds the image.

Sensors

Pair a Linux device, a phone, or Home Assistant. Ask Fizz about the readings. Set an alert. Phone-call alerts use the same monthly cap as gateway approvals.

Open Sensors

  • Hosted at fizzlayer.com/sensors, and self-hosted with the sensors images.
  • MCP for sensor data is a separate server at /api/mcp, with fizz_agent_ tokens.
  • The gateway does not replace that server. You can add it later as one upstream.
